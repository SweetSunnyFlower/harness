## 1. 已确认的目标

完整移植 pi-durable 的能力和行为语义，采用 Go 风格 API，运行时不依赖 Node.js。分阶段交付用于控制依赖和验证成本，不缩减最终功能范围。

跨语言存储互操作是明确的验证目标：TypeScript 创建存储，Go 打开并接续受支持任务，再由相同基线的 TypeScript 实现重新打开。用户对此的要求是“最好可以”；因此必须报告实测覆盖范围，不能把尚未验证的互操作描述为既有保证。核心能力移植和跨语言互操作分别记录完成状态。

开发测试可以运行固定基线的 TypeScript 参考实现。运行 Go 交付物不要求安装 Node.js，也不通过 Node 子进程或服务执行核心能力。Code Mode 仍执行 JavaScript，但由 Go 承载的 QuickJS/WASM 提供执行环境。

完整范围包括持久化内核、Agent 运行时、扩展、工具、Code Mode、观察接口、内置后端与平台适配。浏览器或 Cloudflare 专属能力需要对应宿主；本机 Go 二进制不因实现了接口就自动具备这些平台能力。

## 3. 方案选择

采用原生 Go 内核与宿主适配，Code Mode 优先采用 Go 内嵌 QuickJS/WASM。候选 WASM 宿主为 wazero，其 Go 宿主函数机制适合实现时钟、随机数和工具桥接，但尚未验证上游 QuickJS 模块的完整 ABI、回调和资源限制行为。

备选方案是通过 CGO 承载原生 QuickJS：满足无 Node.js 要求，但增加交叉编译与部署成本，并改变上游 WASM 的执行条件，不作为首选。

不以另一个 JavaScript 引擎的基本语法兼容替代确定性兼容，不通过伪造指纹宣称可以恢复上游 Code Mode 任务。若首选承载方式不满足行为要求，应记录证据并调整实现方案；不得将 Code Mode 从完整范围中删除。

核心包、持久化协议和调度器不依赖具体模型供应商、SQLite 驱动、文件系统或 WASM 引擎。具体依赖版本与公开 Go 符号在相应子项目设计中确定，本总规格规定其必须满足的边界与验收条件。

## 6. 输入、执行与恢复

一次输入的生命周期为：原子接纳输入及所需任务记录，调度生成阶段，调用模型，保存响应与工具任务，执行工具，保存工具结果，再生成或结束 Submission。

### 6.1 输入接纳

Submit 返回可通过持久化 ID 重新获取的 Submission。相同会话中的 requestId 用于提交去重，重启后仍生效。支持在宿主已有事务内接纳输入，结果在外层事务成功前属于暂定状态。

忙闲约束、steer 和 follow-up 的放置时机依照上游规范实现。失败后的排队输入按配置继续、等待或撤回，不擅自改变默认行为。

### 6.2 阶段与副作用

任务由命名阶段和 JSON 检查点驱动。外部副作用之前先保存所需输入及执行意图，调用在事务外发生，结果与下一阶段随后原子提交。

崩溃恢复从检查点重新进入阶段，不恢复 goroutine 栈。时间、随机值和可变配置等需要跨重试稳定的输入必须先保存。等待、重试退避和休眠持久化其条件或截止时间，不为每个睡眠任务保留执行 goroutine。

close、主动 Abort 与进程崩溃按照上游不同规则处理。崩溃次数和模型请求尝试次数按阶段计入相应限制，不能无限恢复导致持续崩溃的任务。

### 6.3 工具重放

工具默认 replay-unsafe。在执行前完成参数验证及 beforeTool，保存最终参数和解析后的重放策略。恢复不重新执行 beforeTool，不因注册表声明变化而将已保存的 unsafe 调用升级为 safe。

safe 工具可以使用保存的参数重新执行，仍需自行确保外部副作用幂等。unsafe 工具在执行中断后产生中断结果。已存储结果的嵌套调用复用原结果，并校验调用键、目标与参数。

框架不保证任意外部副作用恰好一次。重点测试“外部操作成功但结果尚未提交”的不确定窗口。

### 6.4 所有权与取消

历史父子关系与任务所有权分开建模。Abort 按所有权传播，自下而上结束所属工作；父任务 outcome 已决定而子工作尚未结束时保持 completing。

background 形成显式边界，普通父取消与 idle 等待不穿透该边界；显式包含后台工作的取消遵循上游规则。

等待方法的 context 取消只结束当前等待，不取消持久化任务。任务执行使用自身生命周期 context。非协作 Go 扩展无法被安全强制终止；关闭的等待行为如实反映仍未返回的执行。

## 7. 事务、存储与跨语言协议

一个 Session 拥有一条提交串行线。独立任务的外部工作可以并发，但提交必须按序、原子地采纳。事务不包含模型、网络、shell 等外部调用。

Storage 在批次持久化后且下一批开始前采纳该批次。普通提交在采纳后发布；若存储已采纳后又返回错误，该已提交批次仍有效，同时 Session 失败。不得将它回滚或重新发布。

存储持有的输入和返回的可变值必须隔离。Go 的 map/slice 不能绕过事务修改内部状态。文档编辑句柄在事务结束后失效；通过显式编辑接口或受控复制实现上游行为，不假定 Go 具备 JavaScript Proxy。

### 7.1 协议兼容

- SQLite 对齐基线 schema version 2、迁移历史、表与索引、前缀及 JSON 记录格式。
- JSONL 对齐 format version 1、main.jsonl 提交标记、文档及任务 sidecar、ordinal、恢复与回收协议。
- 保留 ID、Seq 的顺序与命名空间；互操作编码遵守上游数值范围，不能利用 Go 更大整数范围写出 TypeScript 无法精确处理的值。
- 严格区分缺失字段、null、空对象和空数组；保留协议允许的未知 JSON 内容。文本、数值及相等性操作按上游语义实现。
- 实现 Chord delta 编解码、应用、历史物化、版本边界及分叉策略。对象序列化顺序不同不等于状态不同，但操作顺序不能改变。
- 文档读取必须遵守 incarnation 的半开生命周期；当前值、历史值、退休状态和地址替换不可混淆。
- 请求分页保持排序、祖先可见范围和游标规则。游标只承诺同后端同类扫描的往返，不额外承诺跨后端通用。
- 缺失必要 base、无效 delta 或已确认数据损坏必须报错，不能当成记录不存在。

### 7.2 持久化强度

普通进程崩溃恢复、断电恢复和宿主故障恢复分别描述。SQLite 的 WAL/synchronous 设置与 JSONL 的 fsync、提交标记及回收顺序按基线契约实现，不把“写入返回”统一描述为断电不丢。

JSONL 只恢复完整且经主提交标记确认的记录，处理撕裂尾行和未确认 sidecar 尾部。回收在授权提交之后执行，遵循 fsync 模式的额外顺序要求。

### 7.3 延迟提交

仅符合上游条件的文档进度变更允许延迟持久化：修改现有、latest、initial-fork 的会话文档，且不包含其他必须立即持久化的写入。

watch 和会话视图可先观察内存采纳的进度；持久化提交观察者只观察真正保存的状态。依赖该文档的后续提交、期限及关闭触发相应刷盘。崩溃可能丢失允许延迟的进度，任务决策和输入不能借此绕过持久化。

### 7.4 接管边界

同一份存储同一时刻由一个进程拥有。TS/Go 接管测试采用显式关闭或确认旧进程退出，不增加跨进程多写者保证。

内置任务恢复要求匹配名称、版本、检查点和行为。自定义任务或工具还要求两侧安装匹配实现；存储不包含 TypeScript 函数代码。

未知或较新的任务定义保留并阻塞，等待兼容实现或迁移。无迁移的较新数据库格式拒绝打开，不进行有损降级。

## 8. Go API 与观察接口

公开 API 使用 context.Context、显式错误、类型化 ID 和配置对象。持久化协议采用与上游兼容的字段，不让 Go 字段命名决定落盘格式。

任务、文档、工具和模型通过小接口连接。泛型用于保持输入、检查点和结果类型关系；存储边界保留可验证的 JSON 表示。宿主无需读取内部实现即可注册扩展和替换后端。

用户观察回调不在 Storage 的同步采纳过程内运行，也不被提交线等待。慢消费者采用上游允许的增量折叠、快照或补页语义；不得静默丢失终态或把收敛视图描述成完整审计日志。

提交观察、文档观察、会话视图、transcript 与任务图分别承担自身契约，不创建另一份独立维护且可能分叉的“真实状态”事件库。

只读打开不恢复、不调度、不允许写入。读操作的取消不改变持久化任务。检查与报告能够区分 pending、blocked、sleeping、failed 和正常关闭。

## 9. 错误与资源生命周期

| 边界 | 行为 |
|---|---|
| Storage 操作失败 | 除规范中的只读请求错误和读取取消外，使 Session 失败并关闭；保留首个原因 |
| 已采纳后 Storage 报错 | 保留已提交状态与发布，随后使 Session 失败 |
| 无效读取或读取取消 | 只影响该次读取，不终止 Session |
| 用户事务回调失败 | 回滚尚未提交的事务；存储已失败时不能因回调捕获错误而继续提交 |
| 任务阶段失败 | 该任务 faulted，按所有权规则处理所属工作 |
| 工具失败 | 形成工具错误结果；保留结构化输出及诊断的上游规则 |
| 任务定义缺失或迁移失败 | 保存任务并阻塞；注册表变化后按契约重新评估 |
| Hook 失败 | 报告并按该 Hook 的规则处理；beforeTool 失败阻止调用 |
| 用户监听器失败 | 报告并结束相应监听或隔离该调用，其他观察者继续 |
| Session 内部记账或必要注册表快照失败 | Session 失败，避免内存状态落后或调度失去依据 |

Go error 与可捕获的扩展 panic 在对应用户代码边界归一化，不能吞掉内部不变量失败或承诺从进程级故障恢复。取消、超时、业务失败与存储失败可以被调用方区分。

关闭释放模型流、文件句柄、定时器、订阅和沙箱实例，等待需要结算的调用。尚未返回的非协作扩展会延迟关闭；不宣称已释放仍在使用的资源。

## 10. Code Mode 与宿主适配

Code Mode 的首选实现包含固定版本 QuickJS WASM、上游 prelude、Go 宿主桥和确定性调度。基线使用 quickjs-wasi 3.6.2。

兼容条件包括：虚拟时钟、UTC、相同随机种子与算法、受限内建能力、工具及 global 调用、Promise 队列推进、结果投递序号、issued 计数、堆栈与堆限制、超时及中断行为。

VM 指纹必须准确反映引擎版本、prelude、确定性协议与限制。恢复时校验 start 数据、journal、调用目标和参数、firstIssued/issuedAfter；不匹配时按上游产生错误并停止新增调用。

复用已保存结果不需要重开 VM。未结束脚本只有在跨运行时测试通过后才声明可接续。存储兼容、脚本功能等价和运行中脚本可迁移是三个不同验收项。

Go 承载同一 WASM 仍不自动保证相同执行语义。对应子项目先验证 ABI、宿主回调、队列、资源中断和参考重放，再扩展完整桥接。这是有明确通过条件的技术风险，不是可省略的能力。

平台适配分别验收：

- 本地环境提供实际文件、命令和监听能力；bash/PowerShell 依赖相应系统命令，缺失时返回明确错误。
- IndexedDB 在浏览器宿主验证，包含事务及单所有者要求。
- Cloudflare 存储与唤醒在对应宿主验证，包含平台事务和生命周期行为。
- Chord Store 适配验证共享提交队列、ID 与原子事务，不以外部数据库的近似接口代替。
- 平台需要桥接时，桥接限于平台 API；持久化和调度核心仍在 Go 中，不引入 Node 服务。
- 图像实现验证方向、尺寸、格式、输出限制与错误行为；需要互操作的结果作为持久化输出保持稳定。

## 11. 验收策略

### 11.1 追踪与参考测试

维护能力追踪表，关联固定基线规范、源码导出和测试组。每项具有明确通过条件、Go 实现位置、自动化证据及适用宿主。

使用可控时钟、模拟模型和确定性工具执行参考场景。对比持久化记录、终态、可观察状态及规范要求的顺序；不比较 goroutine 调度或规范未承诺的偶然顺序。

开发使用的 TypeScript 测试工具与运行时产物隔离。凭证不写入夹具；真实供应商测试采用受控账户并单列，未运行的项目明确报告。

### 11.2 四类核心测试

1. 语义一致性：所有后端的契约测试、文档历史与版本、调度、fork、取消、队列、Hooks、观察和压缩。
2. 双向互操作：TS 写入、Go 读取及修改或恢复、TS 再打开；反方向也覆盖。含 SQLite 与 JSONL、非空 delta 尾部、退休文档、分叉、睡眠、嵌套任务和迁移。
3. 故障注入：提交前、持久化后采纳前、采纳后返回前、模型流中、工具效果后结果提交前、休眠、压缩及 JSONL 回收等边界。验证不确定结果与去重，不把安全工具重试误报为恰好一次。
4. 并发与隔离：Go race 检测、受控资源计数、取消后释放、慢订阅者、存储故障传播和沙箱限制。测试适配真实执行的模型与宿主能力。

Code Mode 额外运行确定性重放和指纹不匹配测试，包括随机、时间、并行工具、失败、取消、store/load 及调用序列分歧。

### 11.3 完成标准

- 所有范围内能力均有实现和通过证据，平台接口占位不算完成。
- 对照测试不存在未解释的语义差异；明确区分允许差异、兼容限制和缺陷。
- Go 运行验证不要求 Node.js；完整 Code Mode 示例也符合此要求。
- 跨语言支持声明只覆盖已验证的格式、版本、任务类型、VM 条件和宿主。
- 保留未知数据与不支持版本的失败行为有测试，不做静默损坏或有损降级。
- 使用文档说明安装、模型与工具接入、持久化、恢复、取消、故障处理及兼容边界。
- 存储查询、调度扇出、长历史和输出流具备基准记录；性能数值单独报告，不冒称与上游相同。

## 12. 分阶段交付

本文件是总设计。各阶段在实现前形成自身规格和详细实施计划；先完成兼容基础的设计与计划，再按依赖推进。阶段完成与整个移植完成分别报告。

| 阶段 | 内容 | 阶段出口 |
|---|---|---|
| 1. 兼容基础 | 记录协议、Chord delta、Memory/SQLite/JSONL、迁移和参考夹具 | 三后端契约通过，SQLite/JSONL 双向读写与历史物化通过 |
| 2. 持久化内核 | Session、事务、文档、fork、观察基础、任务树、睡眠、取消和恢复 | 事务故障、任务状态机、所有权与重启测试通过 |
| 3. Agent 运行时 | 模型适配、输入队列、生成与工具循环、压缩、事件和用量 | 模拟模型与真实适配验证，内置任务跨语言接续通过或明确报告差异 |
| 4. 完整扩展 | Registry、Hooks、热更新、嵌套工具、内置工具、搜索、图像、遥测 | 各公开能力有实现与参考测试；资源与错误边界通过 |
| 5. Code Mode 与平台 | Go WASM 宿主、完整 Code Mode、平台后端及宿主适配 | 脚本功能与重放验证、相应平台实测、完整清单审计 |

Code Mode 和平台适配的可行性验证安排在各自实现开始时，且在需要依赖其结论的公开契约冻结之前完成。若验证失败，先处理方案，不将待验证状态当成通过。

每阶段交付可运行示例、必要文档、对应测试和兼容状态。API 的最终函数签名、依赖版本和文件级工作项属于对应详细设计与计划；不得在没有设计依据时直接扩展为新产品功能。

## 13. 明确的非目标

- 不移植整个 Pi 编码助手产品、终端 UI 或编辑器集成。
- 不保证任意 TypeScript 扩展源码可以在 Go 中直接加载。
- 不保证任意外部副作用恰好执行一次。
- 不支持同一存储的跨进程并发多写者或 CRDT 合并。
- 不保证任意上游未来版本可无迁移打开。
- 不提供规范以外的自动损坏修复、JSONL 全局压缩或非协作 Go 代码强制终止。
- 不要求在原生 Go 本地进程中无宿主模拟全部浏览器和云平台 API。

以上非目标遵循已确认边界及上游规范，不排除完整能力清单中的平台适配、扩展机制或 Code Mode。
